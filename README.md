# 屏幕取字 · ShortX 脚本

一个 ShortX（ExecuteJS）剧本：**全屏悬浮指针**，拖到文字上松手即取字；按住不动 1.5 秒进入**框选截图**。

本仓库收录两个发行版，**导入哪个就用哪个**（两者 `id` 与标题相同，后导入的会覆盖前一个）：

| 版本 | versionCode | 取字结果 | 适合 |
|---|---|---|---|
| **v7.80** `latest` | **108** | 先弹**选字面板**，按词/按字挑完再点「复制」 | 想挑词、复制片段、截图后保存或分享 |
| **v7.33.11** `classic` | **50** | 直接写剪贴板 + 吐司，无面板 | 只要「指哪取哪」，体量小、路径短 |

> 只支持 ShortX 运行环境（脚本调用 `shortx.getUiAutomation()`、`shortx.getShortXDir()` 和 ShortX 的 OCR 类）。不依赖 ShortX 的独立实现是另一个 APK 项目，不在本仓库。

---

## 两个版本差在哪

| | v7.33.11 | v7.80 |
|---|---|---|
| versionCode | 50 | 108 |
| 指针取字 | a11y 文本 → 剪贴板 | a11y 文本 → 选字面板 → 复制 |
| 框选截图 | 选区 OCR → 剪贴板 + 归档 DCIM | 先弹面板（缩略图 + 选区文字）→ 复制 / 保存 / 分享 |
| 选字面板 | 无 | 位图渲染、词/字切换、多选、拖动框选、连续滚动 |
| 分词 | — | ICU 中文分词，**一个词一块**（单块 ≤ 12 字保护） |
| 截图缩略图 | 无 | 有，最多 108dp 高 |
| SwitchCase 分支 | 5 | 4 |
| 脚本写文件 | 不写 | 只写 `Download/屏幕取字_probe.log`（诊断） |
| 脚本弹吐司 | 有 | 没有（吐司交给 ShortX 动作） |
| 导入文件 | 241 KB | 403 KB |

一句话选型：**要挑词、要分享截图 → v7.80；只想快速把字拿到手 → v7.33.11。**

## 安装

1. 下载对应版本的导入文件：
   - v7.80：`dist/v7.80/屏幕取字_V7.80_ShortX导入.txt`
   - v7.33.11：`dist/v7.33.11/屏幕取字_V7.33.11_ShortX导入.txt`
2. 传到手机（任意目录），打开 ShortX → 剧本列表 → **导入**，选择该 txt。
3. 若已存在同名「屏幕取字」，选择**覆盖安装**（versionCode 更大的一版会替换旧版）。
4. 进入剧本，确认已授予**无障碍 / UiAutomation** 与**截图**权限。
5. 给剧本绑定触发方式（手势、磁贴、悬浮球、长按等，脚本本身不注册触发）。

> **两个版本不能同时装。** 导入文件用同一个 `id`（`SHARED-DA-9b1b6b4f-…`）和同一个标题「屏幕取字」，ShortX 会按同一个剧本覆盖。确实要并存时，导入前把 txt 顶部的 `"id"` 和 `"title"` 各改一处（两处保持一致）再导入。

## 使用

### v7.80

| 操作 | 结果 |
|---|---|
| 拖动指针到文字上，松手 | 取字并弹出**选字面板** |
| 按住不动 1.5 秒 | 进入框选模式（箭头变选框） |
| 框选模式下拖出选区，松手 | 截图 → OCR → 弹面板（带缩略图） |
| 点词块 | 选中 / 取消选中（加选） |
| 已选 ≥ 2 块，按在已选块上拖 | 区间取反（反选） |
| 在文字区上下边缘拖动 | 自动跟着滚 |
| 按在空白处上下拖 | 滚动；水平拖不动 |
| 「词/字」 | 切换 ICU 分词 / 按字切块 |
| 「清空 / 全选」 | 按当前是否有选中自动换字 |
| 「复制」 | 选中才亮，点后文字进剪贴板并关闭面板 |
| 「保存」「分享」（仅截图模式） | 存进 `DCIM/Screenshots` / 拉起系统分享 |
| 点面板外 / 第二指 | 关闭面板，不产生结果 |

面板没有「无操作自动关闭」，会一直开着，直到你显式结束。

### v7.33.11

| 操作 | 结果 |
|---|---|
| 拖动指针到文字上，松手 | 取字：文字写剪贴板，吐司显示内容 |
| 按住不动 1.5 秒 | 进入框选模式（箭头变选框） |
| 框选模式下拖动选区，松手 | 截图 → 选区 OCR → 写剪贴板 → 归档到 DCIM |
| 框选模式下按住不动 1.5 秒 | 静默退出框选，回到取字态 |
| 任意时刻第二指按下 | 取消，吐司「用户取消」 |

## 返回给 ShortX 的 JSON

脚本通过 `finishWithJson` 返回，导入文件的 SwitchCase 用 `pointerJson`（或 `jsRet`）读取。两版都把「选没选中字 / 是存图还是分享」放在 JSON 里，由动作链分流：

- v7.80 只保留导入侧真正读的字段：`visualRect` / `captureRect` / `pickedText` / `cancel` / `areaAction`。
- v7.33.11 保留 `ok` / `type` / `code` / `message` / `value` / `data`。

字段级细节见脚本头注；改字段前先确认导入文件的 MatchJS 有没有读它。

## 依赖与权限

| 项 | 必需 | 说明 |
|---|---|---|
| ShortX | 是 | 提供 UiAutomation、截图、OCR |
| 无障碍 / UiAutomation | 是 | 取字主路径；未就绪时退回 OCR |
| 截图权限 | 框选需要 | 由 ShortX 提供 |
| root（`su`） | 存图 / 分享需要 | 指令链里用 `su -c` 搬图、刷库、起 `am` |

**v7.80 的指令链只有三条短命令**（截图存图 = ①②，截图分享 = 吐司 + ①②③）：

| 步骤 | 命令 | 作用 |
|---|---|---|
| ① | `mv -f /data/system/shortx_*/data/screenshots/*.png /sdcard/DCIM/Screenshots/` | 从 ShortX 私有目录搬进相册目录 |
| ② | `content call --uri content://media --method scan_file --arg "$f"` | 让媒体库收录这一张 |
| ③ | `am start -a android.intent.action.SEND …` | 只有「分享」分支才有 |

**v7.33.11 只有两条**：`mv -f /data/system/shortx_<实例>/data/screenshots/* …` 把图搬进相册，再用 `am broadcast MEDIA_SCANNER_SCAN_FILE` 让媒体库扫这个目录。

> v7.80 的 ① 用 `/data/system/shortx_*` 通配，重装 ShortX 不用改。
> v7.33.11 的 ① 写死了实例后缀（`shortx_YfQpDzKzhqrhYpbE`），重装或清数据后要改成新目录，否则 `mv` 静默失败、相册里没有图。没有 root 也能取字和框选，只是图留在 ShortX 私有目录。

## 常见问题

**导入后提示「取字正在进行中」？**
单实例防护拦了第二次运行。等上一次会话结束；若卡住，强停 ShortX 再试。

**重启后第一次运行，有吐司但没有箭头？**
v7.33.5 起已有三级屏幕指标回退 + `abortBuild` 兜底。若仍复现，先确认同一触发没有被绑定两次。

**词模式还是一整句 / 一块好几个字？**
v7.80 起不再合并词块，ICU 切出多少块就排多少块。打开 `Download/屏幕取字_probe.log` 搜 `PANEL_SEG`：`src=icu` 是正常分词，`src=char` 说明这台机器的 ICU 中文词典没起来、退回了按字切；单块最多 12 字，超长会按标点再切。

**保存了但相册里没有图？**
先确认给了 root；再确认 ShortX 私有目录存在（两版的 `mv` 源路径不同，见上表）。v7.80 的分享走 `am start`，ColorOS 等 ROM 可能还需要允许 ShortX 后台启动。

**取到的是整段文字而不是一个词？**
a11y 命中返回的是控件节点文本，属预期行为；要按词挑请用 v7.80 的面板。

**云闪付、游戏里取不到字？**
这些页面 a11y 拿不到节点，脚本会走 OCR，需要 ShortX 的 OCR 可用。

## 校验

```bash
sha256sum -c SHA256SUMS.txt
python3 tools/verify_dist.py
```

前者核对哈希，后者核对两版的 `versionCode`、标题、动作结构，以及「导入文件里的 `expression` 与母版逐字节一致」。都在仓库根目录执行；CI（`.github/workflows/verify.yml`）在每次 push 时跑同一脚本。
